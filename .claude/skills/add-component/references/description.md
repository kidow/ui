# description 작성법 — MCP 검색의 유일한 표면

## 왜 중요한가

shadcn CLI/MCP의 검색은 레지스트리 인덱스를 받아 **`name`, `title`, `description` 세 필드에만**
fuzzy 매칭한다 (`fuzzysort`, keys: `["name","title","description"]`). 검증됨:

- description에만 있는 단어로 검색 → 잡힘
- description에 없는 단어로 검색 → **0건**
- `meta`, `categories`, 소스 코드는 **검색 대상이 아님**

즉 `meta.useCases` 같은 필드를 아무리 잘 써도 에이전트는 그 컴포넌트를 못 찾는다.
**description이 곧 검색 색인이다.**

## 포맷

세 부분을 한 덩어리로. 2~3문장, 마침표로 끊는다.

```
<무엇인가>(영문 일반명 1~2개). <언제 쓰는가 — 구체적 상황 2~3개>. <주요 옵션/특징>.
```

예시:

> 콘텐츠를 끊김 없이 흘려보내는 가로/세로 마퀴(marquee, ticker). 로고 월(logo wall), 고객 후기 슬라이더, 파트너사 나열처럼 목록을 자동으로 계속 흐르게 할 때 쓴다. hover 시 정지, 역방향, 반복 횟수 조절 지원.

여기서 검색에 걸리는 단어들: `마퀴` `marquee` `ticker` `로고` `logo wall` `후기` `슬라이더`
`파트너` `자동` `흐르` `hover` `역방향`.

## 규칙

1. **영문 일반명을 반드시 넣는다.** 에이전트는 `marquee`, `carousel`, `bento`, `testimonial`,
   `pricing table` 처럼 영어로 검색한다. 한국어만 쓰면 그 쿼리에 안 잡힌다.
   괄호로 자연스럽게 넣어 문장을 해치지 않는다.
2. **"언제 쓰는가"를 구체적 상황으로 적는다.** "다양한 곳에 활용 가능" 같은 문구는 검색어가
   하나도 없어서 색인 가치가 0이다. `랜딩 히어로 아래`, `가격표`, `설정 화면` 처럼 적는다.
3. **동의어를 흩뿌린다.** `후기 / 리뷰 / testimonial`, `아코디언 / 접기 / FAQ`.
   억지로 나열하지 말고 문장 안에서 자연스럽게.
4. **복합어는 붙은 형태 그대로 넣는다.** fuzzysort는 연속된 부분 문자열을 찾으므로,
   `자동으로 계속 흐르게` 라고 써두면 `자동 스크롤` 쿼리에 **안 잡힌다**(실측).
   실제로 검색될 법한 표현(`자동 스크롤`, `무한 스크롤`, `infinite scroll`, `logo wall`)을
   그 형태 그대로 문장에 포함시킨다.
5. **핵심을 앞에 둔다.** 목록 UI에서 뒤가 잘려 보일 수 있다. 매칭은 전체 문자열로 되지만
   사람이 읽는 첫인상은 앞 한 문장이다.
6. **키워드 나열식 꼬리는 붙이지 않는다.** `... 키워드: marquee, ticker, logo` 같은 형태는
   사이트 상세 페이지에 그대로 노출돼 지저분하다. 문장 안에 녹인다.
7. **title도 검색 대상이다.** `Marquee` 처럼 영문 일반명으로 둔다.

## 자가 점검

아이템을 추가한 뒤 실제로 검색해본다.

```bash
pnpm dlx shadcn@latest search @kidow -q "<영문 일반명>"
pnpm dlx shadcn@latest search @kidow -q "<쓰임새 단어>"
```

두 쿼리 다 안 잡히면 description을 고친다. 배포 전이라 원격 URL이 없으면
`components.json` 의 `@kidow` 를 임시로 `http://localhost:<dev포트>/r/{name}.json` 로 바꿔
확인하고 반드시 되돌린다.
